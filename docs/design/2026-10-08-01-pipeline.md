# 会话话术挖掘管线

## 1. 目标与范围

从全量 Pi sessions 中提取用户发言，按**语义合并后的句式**统计频率与项目覆盖，产出：

1. **资产候选清单**：可进入 `AGENTS` / skill / prompt / notes 的候选项
2. **用户画像摘要**：协作风格、红线、工具习惯、投入分布

本设计覆盖提取、清洗、语义合并、排序分级与渲染。不覆盖候选通过后的 skill 脚手架生成。

## 2. 现状与约束

- Sessions 为 JSONL 树；用户发言在 `type=message` 且 `message.role=user`
- 内容可能是字符串，或 `[{type:"text", text:"..."}]`
- 目录按工作路径分组；header 含 `cwd` / `id` / `timestamp`
- 全量约数百 MB；须流式或按文件处理，避免整库载入
- 内容含路径、业务细节；产出默认留在本地 `out/`

## 3. 原则

- 先确定性提取与统计，再可选 LLM 润色
- 频次与**项目覆盖数**同时看，抑制假高频
- 保留纠偏短句，丢弃无信息确认句与纯 slash 命令
- 只出候选，不自动写回规则或 skill

## 4. 方案

### 4.1 管线阶段

```text
sessions/**/*.jsonl
  → extract   用户发言 + 元数据
  → normalize 清洗、近重复合并
  → cluster   TF-IDF 句式/主题聚类
  → rank      频次、覆盖、类型建议
  → render    candidates.* + persona.md
```

### 4.2 提取字段（`utterances.jsonl`）

| 字段 | 说明 |
|---|---|
| `utterance_id` | 稳定哈希（session_id + entry_id） |
| `session_id` | header.id |
| `entry_id` | message entry id |
| `timestamp` | entry timestamp |
| `cwd` | header.cwd |
| `project_key` | 会话子目录名或 cwd 归一化后的项目键 |
| `text` | 拼接后的纯文本 |
| `char_len` | 长度 |
| `source_file` | 相对 sessions 根的路径 |

提取规则：

- 只取 `role=user`
- 拼接全部 `type=text` 块；忽略图片等非文本
- 不解析 active branch；全量 user 节点都保留（fork 回放的重复消息由 normalize 去重）

### 4.3 清洗

丢弃（extract 阶段）：

- 整句匹配 slash 命令（`/resume`、`/compact`、`/session` 等），含多行参数
- 低信息短句：归一化键整句命中 `CONFIRM_KEYS`（`好`、`好的`、`ok`、`继续`、`没问题`、`同意`、`hi` 等），或为单个字母 / 数字的选项回答（`A`、`1`）；`执行`、`开始` 等指令不属于低信息短句

保留：

- 纠偏短句：归一化键含 `CORRECTION_MARKERS`（`先别`、`不要`、`不需要`、`只讨论`、`don't` 等）的 phrase 标记 `is_correction`

归一化键 `normalize_key`（不覆盖原文）：NFKC、casefold、压缩空白、去掉首尾标点与符号。

匹配键 `match_key`：在归一化键上把含 `/` 的 token 掩码为路径占位、数字掩码为数字占位，使「同一句式 + 不同路径或编号」合并；掩码后无字母数字内容的键（纯路径、纯数字）不掩码。

### 4.4 语义合并

两级：

1. **近重复**（`services/normalize.py`）：
   - 先丢弃 fork 回放的重复消息（相同 `timestamp` 且相同归一化文本，仅保留首条）
   - 按 `match_key` 精确分组；长度 4~200 字符的键再按字符 bigram Jaccard ≥ 0.85 并查集合并（前缀过滤，避免二次方比较）
   - 每个 `Phrase` 以出现次数最高的原文为代表句，记录 `count` / `project_keys` / 首末时间 / `is_correction` / `utterance_ids`
   - 输出 `NormalizeResult(phrases, input_count, fork_duplicate_count)`，按 `count` 降序；暂不落盘
2. **句式聚类**（`services/cluster.py`）：对代表句的 `match_key` 做字符 2~4 gram TF-IDF；按 `count` 降序做 leader 聚类，与已有 leader 的余弦相似度 ≥ 0.55 则并入最相似者，否则自成新簇（leader 恒为簇内最高频，无链式漂移）

`scikit-learn` 仅用于 TF-IDF 向量化。第一版不做 embedding；若人工抽查发现同义拆散严重，再增加可选 `--embedding` 路径。供应商与模型约定见 [2026-10-08-02-optional-embedding.md](2026-10-08-02-optional-embedding.md)。

### 4.5 排序与候选分级

`services/rank.py` 对 `count >= --min-count` 的 cluster 生成候选，指标：

| 指标 | 含义 |
|---|---|
| `count` | 簇内 phrase 出现次数之和 |
| `project_count` | 去重项目数 |
| `day_span` | 首末出现日期间隔 |
| `sample_texts` | 簇内按 `count` 前 5 条代表原话 |

分级：

- `strong`：`project_count >= --min-projects`，或 `day_span >= 90` 且 `count >= 3 × --min-count`
- `medium`：仅达到 `--min-count`
- 未达 `--min-count` 的簇不输出；leader 为单个绝对路径 / 家目录路径 token 的簇不输出

类型由 leader 的规则关键词粗标，优先级自上而下：

| kind | 判定 |
|---|---|
| `template` | 原文以 `<skill` 开头，或归一化键超过 200 字符（skill / prompt 模板展开文本） |
| `constraint` | 含纠偏标记 |
| `tooling` | 含常见工具名（gh / uv / bun / docker 等） |
| `workflow` | 含工作流动词（commit / push / read / 执行 / 修复 / 审查 / 建议 / 进度 等） |
| `preference` | 含偏好词（使用 / 默认 / 优先 / 简体 等） |
| `other` | 其余 |

建议去向：

| kind | strong | medium |
|---|---|---|
| constraint / preference / tooling | `AGENTS` | `notes` |
| workflow | `skill` | `prompt` |
| template / other | `observe` | `observe` |

LLM 分类为可选后置步骤，不在主路径。

### 4.6 用户画像

由聚合统计 + 强候选约束生成 `persona.md` 大纲：

- 协作风格（是否高频「先讨论」类）
- 红线清单（「不要…」类强候选）
- 工具与工作流习惯
- 项目投入分布（按 `project_key` 发言量）
- 尚不稳定的偏好（高频但覆盖不足）

`services/render.py` 以模板填空生成；红线取 `constraint` 的 strong 候选，不稳定偏好取 `medium` 候选，项目分布按 `project_key` 发言量并以 `cwd` 展示（家目录写作 `~`）。簇命名可用可选 LLM。

### 4.7 CLI 与包结构

```bash
pi-mine extract [--sessions-dir DIR] [--out DIR]
pi-mine mine    [--out DIR] [--min-count N] [--min-projects N]   # 读取 out/utterances.jsonl
pi-mine status  [--out DIR]
```

人类可读为默认；叶命令支持 `--json`。`--sessions-dir` / `--out` 经 `Path.expanduser().resolve()` 后再传入 service。

包布局对齐正式工程：

```text
app/
  cli.py
  options.py    # 共享选项与路径展开
  output.py     # human / JSON
  models.py
  commands/     # Click 适配
  services/     # 业务逻辑
```

依赖方向：`commands → services → models`；适配层可依赖 `options` / `output`。

## 5. 影响面

- 仓库 `~/code/fishx/pi-mine`
- 只读 sessions；不修改 `~/.pi/agent/sessions`
- `out/` 含个人语料衍生数据，不提交

## 6. 测试或验证策略

- 用小型 fixture JSONL 测提取、清洗、近重复合并
- 对真实全量跑 `extract` 后检查：发言条数、项目数、Top 句式是否可解释
- 人工抽查 Top 20 候选，标注假阳性率，再调阈值

### 6.1 全量试跑基线

当前默认值：近重复 Jaccard 0.85；聚类余弦 0.55；`--min-count 3` / `--min-projects 3`。全量 sessions 基线：8523 utterances → 7132 phrases → 6698 clusters → 149 candidates（strong 114）；kind 分布 workflow 91 / other 32 / tooling 9 / constraint 8 / template 6 / preference 3。

抽查结论：

- Top 候选以 `commit` / `执行` / `push` 等工作流触发词为主，符合实际习惯；真正的红线与偏好数量少但准确
- 聚类合并整体可信；残余误合并集中在含相同标识符的长文本，以及 URL 与路径互相匹配，量小且不进入 Top

## 7. 迁移与兼容

无历史版本。Session 格式以 Pi 当前 v3 为准；未知 entry type 跳过。

## 8. 明确不做

- 自动修改 `AGENTS.md` 或生成 skill 目录
- 上传原始 session 文件到外部服务；可选 embedding 仅可发送 normalize 后的 phrase 代表句
- 第一版 embedding 与强制 LLM 总结
- 分析 assistant 全文（除非后续单开「上下文增强」）
- 会话文件删除或归档（与 `sessions-clean` 无关）

## 9. 开放项

- 疑问 / 探查类短句（`你怎么看`、`卡住了`）当前落入 `other` → `observe`，是否单设类型待首轮人工裁定后再定
- 是否需要把「已在 AGENTS 出现的句子」标成 `already_codified`
- 可选 embedding / LLM 命名的触发条件
